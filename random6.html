MathML corner cases for TalkBack

Each section contains one equation designed to stress a specific part of the MathML → Android accessibility tree → TalkBack speech pipeline. Navigate with linear swipe, by-character / by-word granularity, and "explore by touch". Compare speech with the Expected note.

1. Deeply nested continued fraction

x= 1+ 1 2+ 1 3+ 1 4+ 1 5+⋱

Why: recursion depth, fraction start/end disambiguation, and the diagonal ellipsis (U+22F1) which many speech tables lack.

Expected: clear nesting boundaries ("fraction 1 over 2 plus fraction… end fraction"), no dropped levels, "down right diagonal ellipsis" (not silence or "unknown").

2. Invisible operators

f⁡(x) = 2⁢x + ai⁣j + 3⁤12

Why: U+2061 FUNCTION APPLICATION, U+2062 INVISIBLE TIMES, U+2063 INVISIBLE SEPARATOR and U+2064 INVISIBLE PLUS have zero width. Implementations may read their Unicode names, ignore them, or create empty focusable nodes.

Expected: "f of x equals 2 x plus a sub i comma j plus 3 and one half" — no "function application", no empty swipe stops.

3. Prescripts with mmultiscripts and <none/>

U 4+ 92238 , R i j k μ

Why: pre-sub/superscripts, <none/> placeholders, and interleaved tensor indices. Order of reading is often wrong, or none is announced.

Expected: "U, pre-subscript 92, pre-superscript 238, superscript 4 plus"; tensor indices in correct positions; never "none".

4. Matrix with empty cells, spans and stretchy bars

| ac d+ef 0⋯ | =0

Why: empty <mtd>, columnspan, ragged rows, and stretchy vertical bars (determinant vs absolute value). Tests table row/column counts exposed via CollectionInfo/CollectionItemInfo.

Expected: "3 by 3 matrix" (or determinant), correct row/column indices, empty cells announced as "blank" rather than skipped or crashing navigation.

5. Ambiguous delimiters: half-open intervals and nested absolute values

[0,1) ∩ ]−1,12] , |a|b|c|

Why: mismatched brackets, reversed ']' as opening fence (French notation), U+2212 MINUS vs hyphen, and |a|b|c| which is genuinely ambiguous (|a|·b·|c| or |a·|b|·c|).

Expected: each delimiter spoken individually and literally; TalkBack must not "auto-pair" delimiters or say "dash" for the minus sign.

6. Accents vs. over/underscripts and large operators

lim n→∞ ∑ k=1 n 1k2 = v→ ⋅ x^ + a+b¯ + x+⋯+x⏞ n times

Why: lim as a multi-char <mo>, sum limits, accent="true" (should read "v vector", "x hat"), a bar over a group (conjugate/mean), and a nested overbrace with text annotation.

Expected: "limit as n approaches infinity of sum from k equals 1 to n…", "v vector", "x hat", "a plus b bar", "overbrace … n times".

7. Unicode stress: math alphanumerics, primes, combining marks, astral plane

𝔽: ℝn → ℂ , f″(x) + g' + x̃ + 𝒜𝒷 + sinx

Why: surrogate pairs (𝔽 U+1D53D, 𝒜 U+1D49C) break naive UTF-16 character granularity; double prime U+2033 vs ASCII apostrophe; combining tilde U+0303; and <mi>sin</mi> which should be read as a word, not "s i n".

Expected: "double-struck F", "f double prime of x", "g prime", "x tilde", "script A script b"; character navigation must never split a surrogate pair (no "unknown"/replacement chars).

8. Right-to-left math (Arabic notation)

د⁡(س) = س٢ + س٣ − ١٤

Why: dir="rtl" mirrors layout; Arabic-Indic digits (١٢٣٤); a lang switch inside an English page. Tests reading order vs. visual order and TTS language switching.

Expected: logical order (د of س equals س squared plus cube root of س minus one quarter), spoken with an Arabic voice if available; touch exploration geometry must match mirrored layout.

9. Hidden / phantom / spacing content and ARIA overrides

a+ b+ c ≠ (decorative) d = e secret

Why: <mphantom> takes space but is invisible (should it be read?), zero-width <mpadded> with a visible glyph, <mspace>, aria-hidden and aria-label on MathML subtrees, display:none, and empty token elements.

Expected: "a plus c not equal to d equals the Euler number e". Phantom, decorative, display:none and empty tokens must not be spoken nor create empty focus stops; zero-width ≠ must still be reachable by touch.

10. Interactive math: link inside math, focusable math, semantics/annotations

Inline: the identity ei⁢π +1=0 e^{i\pi}+1=0 10 and x2 inside a sentence, followed by π≈3.14159.

Why: math inside an <a>, legacy alttext, <semantics> with TeX and Content MathML annotations (must not be read), a focusable tabindex math with role="img" override, and the MathML href attribute on a token. Inline math must flow with surrounding text.

Expected: link announced once with readable name (not raw TeX, not "e i pi 1 0 eq plus exp times"), double-tap activates; second math reads "x squared, image"; π is announced as a link if href is supported, and no navigation trap occurs.
